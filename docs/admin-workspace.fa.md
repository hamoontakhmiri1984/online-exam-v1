# میزکار کاربر ارشد

- منو در چهار بخش کاربران، محتوا، مالی و سیستم گروه‌بندی می‌شود. مسیرهای اشتراک‌ها، پرداخت‌ها، تأیید گروه‌ها و رویدادها فقط برای کاربر ارشد هستند.
- گزارش‌ها با بازه‌های ۷، ۳۰ و ۹۰ روز و فیلتر مدرس در سرور محاسبه می‌شوند. نتایج، پرداخت‌ها و رویدادها صفحه‌بندی دارند. هیچ درخواست جداگانه‌ای برای دریافت نتیجهٔ تک‌تک آزمون‌ها ارسال نمی‌شود.
- «شروع‌شده» تعداد تلاش‌های شروع‌شده در بازه و «تکمیل‌شده» تعداد تلاش‌های پایان‌یافته در بازه است؛ این دو الزاماً یک مجموعه نیستند. میانگین، میانگین درصد پاسخ صحیح هر تلاش تکمیل‌شده است؛ تلاش بدون سؤال در میانگین وارد نمی‌شود.
- روزهای نمودار بر مبنای زمان تهران هستند و روزهای بدون فعالیت صفر دارند. ثبت‌نام جدید یک شاخص کل سامانه است و با فیلتر مدرس نمایش داده نمی‌شود.
- مبلغ پرداخت‌های موفق به تومان، فقط وضعیت Success و زمان updatedAt را در نظر می‌گیرد. این عدد گزارش حسابداری تسویه نیست. فهرست پرداخت‌ها بر اساس createdAt فیلتر می‌شود. اشتراک فعال مستقل از بازهٔ نمودار، بر اساس آخرین اشتراک فعلیِ منقضی‌نشده محاسبه می‌شود.
- تخصیص دستی اشتراک با تأیید کاربر و ثبت رویداد در همان تراکنش انجام می‌شود. تخصیص اشتراک، پرداخت جدید ثبت نمی‌کند.
- رویدادها اطلاعات حساس before/after را به مرورگر نمی‌فرستند. فقط عملیات دارای audit در این فهرست هستند، نه تمام رفتارهای کاربران.
- فونت Vazirmatn Variable همراه فایل‌های سایت ارائه می‌شود؛ وابستگی به Google Fonts حذف شده است.

## بررسی عملکرد

۱. با کاربر ارشد، میزکار، فیلتر بازه، نمودار و لینک صف گروه را بررسی کنید.
۲. در گزارش‌ها مدرس و بازه را عوض کنید؛ نتیجه و تعداد باید مربوط به همان فیلتر باشد.
۳. در مدرس‌ها و دانشجویان جستجو و ترتیب نام/جدیدترین را امتحان کنید؛ حساب بدون نام باید عنوان جایگزین داشته باشد.
۴. در اشتراک‌ها ابتدا انصراف و سپس تأیید تغییر را بررسی کنید؛ رویداد تغییر باید ثبت شود.
۵. با مدرس و دانشجو به آدرس مستقیم مسیرهای مدیریتی بروید؛ دسترسی باید رد شود.
۶. حالت تاریک، عرض موبایل، Tab و نمایش خطا/تلاش مجدد را بررسی کنید.

```sh
npm test -w client
npm run test:e2e -w client
npm run build -w server
npm run build -w client
npm run lint -w client
```

تست گزارش PostgreSQL و تست تخصیص اشتراک در CI با دیتابیس واقعی اجرا می‌شوند. تست مرورگر با پاسخ‌های کنترل‌شدهٔ API اجرا می‌شود و جای آزمون یکپارچهٔ دیتابیس را نمی‌گیرد.

## اعلان‌ها

- ورود موفق با رمز، OTP یا گوگل یک اعلان شخصی با IP اتصال ثبت می‌کند؛ درخواست کد، ورود ناموفق و تمدید نشست اعلان ورود نمی‌سازند.
- IP از `req.ip` گرفته می‌شود و صحت آن به تنظیم `TRUST_PROXY` وابسته است.
- حذف اعلان فقط برای همان کاربر ثبت می‌شود و پس از تازه‌سازی باقی می‌ماند؛ اعلان عمومی دیگران حذف نمی‌شود. خطای حذف امکان تلاش دوباره دارد.
