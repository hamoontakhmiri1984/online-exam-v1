# تکمیل ورود و ثبت‌نام

مبنای بررسی: commit `4df0548` روی main. این تغییرات نیاز به migration جدید ندارند.

## رفتار

- پس از واردکردن شماره و زدن «ادامه»، کد پیامکی درخواست می‌شود. برای ایمیل، فرم رمز بدون ارسال کد باز می‌شود.
- زیر فرم، ورود با رمز یا دریافت کد با ایمیل در دسترس است. گوگل فقط در مرحله اول حضور دارد.
- «ویرایش» کنار شناسه، مقدار قبلی را نگه می‌دارد و کد/رمز واردشده را پاک می‌کند. بازگشت به شناسه‌ای که در همین جریان کد گرفته، کد جدید نمی‌فرستد. شمارنده با زمان واقعی و به تفکیک شناسه نگه داشته می‌شود.
- حساب موجود گوگل وارد می‌شود. برای حساب جدید، پس از تأیید گوگل نام و نقش کارآموز/مدرس دریافت می‌شود. نقش مدیر قابل انتخاب نیست.
- مدرس جدید از سیاست تأیید مدیر پیروی می‌کند؛ نقش و رد/تأیید حساب موجود با ثبت‌نام گوگل تغییر نمی‌کند.
- اعتبار گوگل در درخواست ساخت حساب دوباره بررسی می‌شود. credential تنها در حافظه فرم است، نه URL یا localStorage.
- بازیابی رمز، شناسه مرحله رمز را نگه می‌دارد؛ شماره فارسی نرمال می‌شود و شرایط رمز قبل از درخواست بررسی می‌شوند.
- ارسال مجدد و تأیید کد هم‌زمان اجرا نمی‌شوند. شش رقم کامل ورود یک‌بار خودکار تأیید می‌شوند.
- تم بین اجزای صفحه مشترک است. جای دکمه ثابت و ورودی کد در موبایل ۳۲۰ پیکسل بدون خروج از عرض صفحه است.
- اصلاح قبلی پیام فارسی خطا و جداسازی محدودیت ارسال کد نیز در این بسته اعمال شده است.

## تنظیم گوگل

`GOOGLE_CLIENT_ID` در سرور و `VITE_GOOGLE_CLIENT_ID` در کلاینت باید مربوط به یک OAuth client باشند. origin کلاینت Codespace باید در تنظیمات Google مجاز باشد. نبود تنظیم کلاینت به‌جای دکمه خراب، پیام عدم دسترسی نشان می‌دهد.

## تست

از ریشه پروژه:

```sh
npm test -w client
node --test server/tests/googleAuth.test.cjs server/tests/authErrors.test.cjs server/tests/sessionAccess.test.cjs
npm run build -w server
npm run build -w client
npm run lint -w client
```

تست دستی با سرور و سرویس‌های Codespace روشن:

1. شماره فارسی → ادامه: یک درخواست پیامک. ایمیل → ادامه: رمز، بدون ارسال کد. تغییر روش/ویرایش و بازگشت به همان شماره، کد تازه نفرستد. رمز اشتباه پیام فارسی بدهد.
2. فراموشی رمز از مرحله رمز → شناسه پر باشد؛ کد واقعی، رمز جدید و ورود با آن را بررسی کنید.
3. روش کد → دریافت، چسباندن شش رقم، کد اشتباه و ارسال مجدد؛ هر بار فقط یک درخواست.
4. گوگل حساب موجود → ورود. گوگل حساب جدید → انتخاب نقش و ساخت حساب.
5. تأیید مدرس روشن → حساب مدرس جدید منتظر مدیر؛ خاموش → ورود. حساب ردشده همچنان مسدود.
6. تغییر تم → رفتن بین ورود/ثبت‌نام/فراموشی رمز؛ ورودی و ویجت گوگل با تم هماهنگ بمانند.

در محیط بررسی، ۸۰ تست کلاینت و ۲۲ تست هدفمند سرور، build هر دو و lint موفق بودند. تست مرورگر با پاسخ‌های API و SDK گوگل شبیه‌سازی‌شده انجام شد. ارسال واقعی پیامک/ایمیل، OAuth واقعی و تراکنش‌های پایگاه داده Codespace باید در محیط شما بررسی شوند.

## مشکل commit

در نسخه بررسی‌شده hook اجباری commit یا تنظیم Husky پیدا نشد. علت خطای commit Codespace بدون خروجی همان دستور قابل تشخیص نیست. از حذف تغییرات، reset سخت و دور زدن hook بدون شناخت خطا استفاده نکنید. اعمال‌کننده در صورت تداخل پیش از تغییر فایل‌ها متوقف می‌شود؛ خروجی تداخل و خطای commit را ارسال کنید.
