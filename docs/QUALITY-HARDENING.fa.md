# سخت‌سازی و نگهداری

## Redis و احراز هویت
فقط کتابخانهٔ `redis` استفاده می‌شود. دو اتصال مستقل نشست و محدودیت درخواست عمدی هستند؛ سلامت هر دو پیش از شروع HTTP بررسی می‌شود. صف offline خاموش است و خرابی Redis روی مسیرهای وابسته پاسخ 503 می‌دهد؛ درخواست حساس پس از اتصال مجدد ناخواسته اجرا نمی‌شود.

هر درخواست احراز هویت، علاوه بر نشست Redis، وجود حساب و تطابق نقش فعلی با توکن را بررسی می‌کند. حذف حساب یا تغییر نقش فوراً روی درخواست بعدی اثر دارد. تأیید مدرس همچنان فقط سیاست نقش Instructor است؛ مدل فعلی برای Student یا SuperAdmin فیلد «غیرفعال» ندارد. خطای زیرساخت نباید به خروج اشتباه کاربر با 401 تبدیل شود.

## محیط و تصویر اجرا
در production، CLIENT_URL باید مبدأ HTTPS غیرمحلی و بدون مسیر، نام کاربری یا رمز باشد. کلیدهای پیش‌فرض یا خالی S3 پذیرفته نمی‌شوند. GOOGLE_CLIENT_ID اختیاری است؛ بدون تنظیم آن، ورود گوگل پاسخ 503 مشخص می‌دهد.

Docker پس از build وابستگی‌های توسعه را حذف می‌کند. Prisma CLI عمداً وابستگی اجرایی است تا `prisma migrate deploy` در فرایند استقرار قابل اجرا باشد. HEALTHCHECK وضعیت `/health` را بررسی می‌کند.

لاگ‌های برنامه از logger مشترک عبور می‌کنند. کد OTP فقط در محیط غیرproduction و بدون سرویس ارسال، برای تست محلی نمایش داده می‌شود. لاگ‌های query خود Prisma و خروجی اسکریپت‌های خط فرمان مستقل هستند. هیچ‌گاه env، بدنهٔ درخواست یا توکن را به لاگ عملیاتی ندهید.

## تاریخچهٔ دیتابیس
نام کامل پوشهٔ migration شامل timestamp است؛ تکرار پسوند نام به‌تنهایی تکرار migration نیست. فایل‌های اجراشده و fixture تاریخی recovery عمداً از تبدیل پایان‌خط مستثنا هستند تا checksum عوض نشود. سایر متن‌ها LF هستند.

در بررسی اولیه، تنها اختلاف تاریخچه با مدل، مقدار پیش‌فرض `approval_policy.updatedAt` بود. مدل با پیش‌فرض CURRENT_TIMESTAMP موجود در migration هم‌راستا شد؛ نیازی به تغییر داده یا migration قبلی نبود.

CI ابتدا migrationها را روی PostgreSQL موقت اجرا و سپس با `prisma migrate diff --exit-code` نتیجه را با مدل فعلی مقایسه می‌کند. این بررسی جایگزین بررسی دیتابیس Codespace یا production نیست. برای بررسی فقط‌خواندنی دیتابیس تنظیم‌شده، از پوشهٔ server:

```bash
npx prisma migrate status
npx prisma migrate diff --from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/schema.prisma --exit-code
```

کد خروج 2 یعنی اختلاف وجود دارد؛ خروجی را بررسی کنید و تغییر لازم را در migration جدید ثبت کنید. دستور `reset` یا بازنویسی تاریخچه راه رفع اختلاف نیست. پوشهٔ recovery برای عیب‌یابی نسخه‌های قبلی حفظ می‌شود.

## تست رابط آزمون
تست مرورگر دانشجو شروع آزمون، انتخاب پاسخ، ذخیرهٔ خودکار، بازیابی پس از refresh و ارسال پاسخ انتخاب‌شده در پایان را بررسی می‌کند. تست‌های قبلی ساعت و صف ذخیرهٔ پاسخ نیز باقی می‌مانند.
